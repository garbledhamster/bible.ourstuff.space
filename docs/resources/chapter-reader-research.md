# Chapter reader research

The Open Chapter reader serves two common jobs. Someone can read the reasoning for a decision, or scan for the task, reference, or asset they need. Use the chapter's existing headings, links, and task records for both.

## Typography and reading

- Give the chapter title, section headings, subheadings, prose, and controls distinct jobs in the type scale. Use weight and spacing as well as size, and keep the heading levels from the chapter source so readers can navigate by heading. Carbon uses separate type sets for task-focused interfaces and long-form reading. Our reader can apply that distinction through DM Sans for interface and working views and Georgia for the Editorial brief. Check which face the browser actually loads in the private reader. [IBM Carbon typography](https://www.carbondesignsystem.com/building-blocks/foundations/typography/overview), [W3C page structure](https://www.w3.org/WAI/tutorials/page-structure/)
- Start with a prose width around `66–70ch` and a line height around `1.6`. USWDS uses font-relative measures and gives `1.62` as an option for extended reading. The width here is a local CSS cap based on the width of the zero glyph. Check actual line lengths with chapter text at desktop widths and let the text wrap into the available space on phones. [USWDS measure](https://designsystem.digital.gov/design-tokens/typesetting/measure/), [USWDS line height](https://designsystem.digital.gov/design-tokens/typesetting/line-height/)
- Check reflow at 320 CSS pixels and check that 200% text resizing preserves content and controls. For the WCAG text spacing check, apply `1.5` line height, `2em` after paragraphs, `.12em` letter spacing, and `.16em` word spacing together. Confirm the layout picker, chapter links, and task details stay usable with the keyboard. [W3C reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html), [W3C resize text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html), [W3C text spacing](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html), [W3C keyboard access](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html)

## Chapter views for specific work

- **Work queue.** Put remaining work, recorded status, assignees, and blockers within reach so a contributor can pick up a task and a coordinator can see where someone is waiting. Atlassian's stand-up practice brings current work and impediments into the same discussion, and its roles play makes unassigned work visible. Use the existing task sheet and its ticket links. Keep Build handoff available for collaborators who need the record of completed and remaining work. [Atlassian stand-ups](https://www.atlassian.com/agile/scrum/standups), [Atlassian roles and responsibilities](https://www.atlassian.com/team-playbook/plays/roles-and-responsibilities), [Project Bible Task List workflow](task-list-workflow.md)
- **Marketing.** Give readers links to the chapter's named audience, positioning, release, and promotional materials where the source supplies them. Adobe's creative brief examples identify audience, messaging, delivery channels, and campaign evidence as context for creative work. The Project Bible already links the release offer to store copy and verified captures. Use those existing section names and links with the full chapter available below. Designers can continue using Illustrative to browse chapter artifacts in context. [Adobe creative brief examples](https://business.adobe.com/au/blog/basics/creative-brief), [Project Bible release guide](game-bible-guide.md#release-pricing--marketing)
